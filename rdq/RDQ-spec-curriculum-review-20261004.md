# RDQ 需求規格：國小四年級審教材機制全面優化（最終確認版）

## 一句話任務
建立四年級專屬「**同型態檔案輸入即輸出、三階嚴格退回修改、集中 reviewed/ 輸出、Before/After 比對與自動化檢核腳本**」的完整審教材機制。

## ✅ 已確認
- **三科平衡推展**：同時涵蓋**南一數學**、**翰林國語**、**康軒社會**，建立完整四年級審查體系（Ⅲ）
- **輸入即輸出同型態原則**：使用者提供什麼類型的檔案（Markdown、HTML、Docx/PDF、純文字等），就直接優化或修正為對應類型的新檔案，文末或隨附提供標準化三階檢測報告（Ⅲ）
- **輸出存放位置集中化**：統一集中存放至專屬輸出資料夾 `reviewed/`，原檔保持純淨，輸出檔保持結構清晰易找（Ⅲ）
- **嚴格退回修改機制**：
  - **第一階（最低門檻）**：未符合四年級先備經驗、108課綱指標、或版本（南一數、翰林國、康軒社）者，**直接打回重置，不給通過**（Ⅰ）
  - **第二階（中階目標）**：CLT 認知負荷、SDGs、STEAM，未達標時**不自動胡亂猜測**，而是列出未達標清單與具體修改建議，經教師確認後才輸出最終版（Ⅲ）
  - **第三階（高階目標）**：迷思診斷、在地生活時事、18項議題，列為加分亮點與診斷標籤（Ⅰ）
- **學校與在地情境**：以**臺中市梧棲區中正國小**為背景，融入梧棲漁港、高美濕地、海線生活特色（Ⅰ）
- **全域技能與專案初始化**：已將 `g4-curriculum-review` 註冊至全域 `~/.gemini/config/skills/` 與懶人包清單中，本專案已初始化並同步遠端 `origin/main`（Ⅰ）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- **輸出檔案命名**：優化後檔案存於 `reviewed/[原檔名]_優化版.[ext]`，並在同目錄產出 `reviewed/[原檔名]_審查報告.md` → 預設採此命名結構
- **檢測報告呈現位置**：Markdown 檔案直接附於文末，HTML 檔案以專屬折疊卡或檢視區塊呈現，Office/PDF 產生專屬對照審查報告

## ➕ 已採納（象限Ⅳ）
- **Before / After 一鍵比對視圖**：提供明確的修改前後差異對照，讓教師一眼看出哪裡被修正
- **考卷格式相容性（Windows Word/PDF 防跑版）**：若處理考卷類文件，套用雙欄排版與字型防跑版規範
- **CLI / 自動化檢核指令**：建立專屬檢核腳本（如 `python scripts/check_curriculum.py`），支援批次審查並輸出報告
- **高階迷思診斷分類代碼表與誘答庫**：為選擇題及各題型建立典型四年級迷思概念代碼（分數加減分母相加、乘除位值混淆等），並附帶診斷標籤
- **安全隔離大檔**：將 `115四上數課習/` 及大型 zip/PDF 列入 `.gitignore`，避免大檔進入 Git 儲存庫

## ❌ 排除項（明確不做）

## 📋 一段式需求規格
本專案為**臺中市梧棲區中正國小**四年級專屬之**教材與試題審查生成系統**。系統嚴格對齊**南一數學**、**翰林國語**、**康軒社會**三科教科書版本。全面實施**同型態檔案輸入即輸出原則**（原檔輸入 → 在 `reviewed/` 目錄產生同型態優化版與審查報告）。嚴格落實**三階漏斗審查機制**（第一階課綱版本紅線嚴格打回；第二階 CLT 認知負荷、SDGs、STEAM 未達標時**列出缺失清單嚴格退回教師確認**；第三階迷思概念與海線情境診斷）。系統建置 **Before/After 修改比對**、**考卷排版防跑版規範**、**批次自動化審查腳本**與**四年級高階迷思代碼資料庫**，同時在 `.gitignore` 隔離大型課本檔案。
